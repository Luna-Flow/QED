# QED formal specification audit matrices

Audit basis: `doc/attachments/qed_formal_spec.typ`, `formal_verification/QEDFV`, and `src/kernel` at the worktree base `ba385bc`. “Lean proved” below means the **stated Lean proposition** typechecks; it does not automatically certify the stronger mathematical sentence in the manuscript.

Status vocabulary is fixed: `proved` means the stated proposition is independently established; `conditional` means it is established only under explicit law/simulation premises; `open` means the required proof or refinement is missing; `bug` means a concrete defect has a reproducer. GitHub references use the repository issues cited below.

## 2026-10-12 typed HOL core follow-up

`formal_verification/QEDFV/HOL` now contains an independent intrinsically typed HOL
core. `Types.lean` constructs actual carriers (`Prop`, `Nat`, functions, and type
variables) and proves non-emptiness. `Evaluation.lean` proves capture-avoiding
renaming, substitution, and beta evaluation laws. `Extensions.lean` proves the
predicate-subtype carrier and Abs/Rep laws used by a typedef witness. `Rules.lean` proves validity
preservation for the typed forms of `REFL`, `ASSUME`, `TRANS`, `MK_COMB`, a
closed-context `ABS`, `BETA`, `EQ_MP`, and the exact assumption-discharge
`DEDUCT` rule, plus term-instantiation validity. These theorems do not yet prove
the correspondence to the legacy `Lean.Expr`/MoonBit syntax, general open-context
`ABS`, or polymorphic `INST_TYPE`; those remain conditional/open below.
