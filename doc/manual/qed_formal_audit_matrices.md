# QED formal specification audit matrices

Audit basis: `doc/attachments/qed_formal_spec.typ`, `formal_verification/QEDFV`, and `src/kernel` at the worktree base `ba385bc`. “Lean proved” below means the **stated Lean proposition** typechecks; it does not automatically certify the stronger mathematical sentence in the manuscript.

Status vocabulary is fixed: `proved` means the stated proposition is independently established; `conditional` means it is established only under explicit law/simulation premises; `open` means the required proof or refinement is missing; `bug` means a concrete defect has a reproducer. GitHub references use the repository issues cited below.

## 2026-10-12 typed HOL core follow-up

`formal_verification/QEDFV/HOL` now contains the formal soundness mainline: an
independently typed HOL core with constructed carriers, non-emptiness, typed
renaming/substitution/beta laws, general open-context `ABS`, exact assumption
discharge `DEDUCT`, typed term instantiation, and typed polymorphic `INST_TYPE`.
`Derivation.lean` closes the corresponding inductive `derivation_sound` theorem.
`Concrete.lean` supplies a closed non-triviality countermodel; `TypeDefinitions.lean`,
`Definitions.lean`, and `Specification.lean` supply typed semantic contracts for
the extension gates. `Transport.lean` proves validity transport and bidirectional
old-language invariance; `Soundness.lean` exposes the model and theorem entry
points, while `Conservativity.lean` keeps the derivation-facing boundary. These
results are the soundness mainline; they do not yet construct a
distinct-state syntactic erasure simulation for the legacy `Lean.Expr`/MoonBit
implementation.
